# 一个任务：从目标到可审查的结果

使用者可以描述需要调查或修改的问题，明确范围、交付物与完成条件，然后查看过程和回执，再决定是否接受结果。MAGR-Harness 的研发 Agent 面向这类任务；通用工作台也提供个人需求记录、补充和规划。个人任务访问仓库或项目知识时，需要关联已有授权的项目。工作台提供计划入口，不代表所有跨领域任务都已通过真实自动执行验收。[GA13 候选说明](general-agent-v1/GA13_RC.md)

## 提出目标并执行

需求不足时可以补充，同一任务的修订保留先前需求；计划用于确认方向、交付物和完成条件。项目任务在获准范围内使用工具和工作区，执行过程、差异及测试回执供审查。CLI 与 SDK 提供任务、事件和产物接口；项目指导、扩展及 MCP 受各自声明和授权约束。[任务规范](general-agent-v1/GA01_TASK_OUTCOME.md) · [CLI 与 SDK](harness-v4/HEADLESS.md) · [项目指导与工具](harness-v4/PROJECT_GUIDANCE_AND_PLUGINS.md)

CLI 请求成功只说明 API 接受了请求；任务是否完成要看响应状态、对应产物和验证依据。具体执行需要的权限、模型配置和环境不会因自然语言需求自动获得。[GA13 命令与限制](general-agent-v1/GA13_RC.md#cli-与-sdk)

长任务可能遇到上下文增长、环境缺失、执行中断或部分结果已发生。上下文压缩和记忆可帮助管理信息，但实验也显示节约输入不必然保持任务质量。已发生的外部动作如果结果未知，应先依据原操作回执对账；不能把一次未知写入直接当作失败并盲目重试。[实验解读](EVALUATION_SUMMARY.md) · [备份与恢复](harness-v4/H18_OPERATIONS.md)

## 数据库已经恢复，运行目录发布失败后怎样继续

这是 **2026-11-19 的实际独立工程复验**，不是一个 Agent 完成业务任务的故事。验收源码 `8a6489b`，在 WSL2 和隔离 PostgreSQL 中对发布权限故障注入做了定向 1/1 复验：

1. 数据库导入已经完成，运行目录发布前父目录权限被设为不可写。CLI 报告 `database_restored: true`、发布失败和 `retry_same_command: true`，保留已导入收据。
2. 恢复权限后，操作者使用相同快照、数据库、目标和命令继续；此时 PATH 中没有 `pg_restore`。剩余发布完成，恢复的 CAS 字节一致，收据清除。
3. 故障时有清理告警并留下空暂存目录，记录没有隐藏这一部分。真实模型调用为 0，生产和原生 Linux 宿主机 **NOT_RUN**。原 146 项是此前源码 `6bcf685` 的结果，不是此次候选重跑的全量成绩。

阶段状态和恢复收据使操作者能判断哪一步已发生、哪一步需要继续；这条记录不证明任意 Agent 任务都能在任意故障下自动恢复。[H18 独立复验](harness-v4/H18_PUBLISH_RETRY_INDEPENDENT_20261119.md) · [机器记录](harness-v4/accept/HV4-H18/publish-retry-independent-20261119.json)

## 何时可以接受结果

执行成功、测试通过、验证回执、业务完成及批准发布是不同的判断。审查时应核对产物所绑定的输入和版本、实际运行的检查与未运行项，以及是否具备需要的审批。候选验证无法自动成为另一版本或另一系统的放行结论。[当前状态](CURRENT_STATUS.md) · [独立质量评测](harness-v4/H12_R08_INDEPENDENT_MATRIX_REVIEW_20261118.md)

当前默认保留单 Agent 执行；受控 H17 实验的委派可用臂没有发生实际专家调用，不能据此比较真实多专家推理的优劣。工作区隔离、Runner、多用户边界和恢复能力应按各自工程记录理解。[H17 独立验收](harness-v4/H17_INDEPENDENT_ACCEPTANCE_20261119.md) · [能力实验](EVALUATION_SUMMARY.md)
