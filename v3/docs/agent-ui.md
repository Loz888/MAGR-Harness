# 项目助手：首次使用与持续协作

首页、`/repo` 和 `/workbench` 使用同一个页面，默认进入 **项目助手**。完成一次模型
配置与项目授权后，每次只需输入需求；任务类型、替换文本、适配器参数和逐次确认
都不属于正常提交流程。原 GitHub 只读分析保留在顶部的 **GitHub 分析** 模式。

## 在自己的电脑启动或升级

需要 Python 3.12、uv、Make、Docker Engine 和 Compose V2。Windows 使用 WSL2
Ubuntu，并启用 Docker Desktop 的 WSL Integration。

在项目的 `v3` 目录依次执行：

```bash
make setup
make deps-up
make migrate
make doctor
make dev
```

若在WSL窗口里直接执行过 `set -e`，先执行 `set +e`。否则任意命令失败都可能结束
当前shell并关闭窗口。需要整段粘贴时，可以使用下面的成功后才继续的写法：

```bash
set +e
cd "$HOME/projects/Magr-Harness/v3" &&
make setup &&
make deps-up &&
make migrate &&
make doctor &&
make dev
```

这是当前工作副本路径，其他安装请换成实际 `v3` 目录。
若 `make deps-up` 提示缺少 `MGAR_V3_DB_PASSWORD`，新版 `make setup` 会从已有的
标准本地数据库连接串补齐该键，保留原凭据，不生成替换密码。远程/非标准连接串或
无法安全转义的密码要求显式配置，脚本不会猜测。不要删除旧 `.env` 或数据库卷来解决。
本次故障与验证记录见[WSL启动修复](repairs/STARTUP-20261112.md)。

项目助手使用 `0040_harness_product.sql` 保存项目许可、持续会话、运行环境、
回写与预览记录；GitHub代码交付另增加 `0045_harness_github_delivery.sql`。
已有安装也必须先停止旧 `make dev`，执行 `make migrate`，再重新
启动服务；只刷新网页不能加载新的后端接口。迁移保留既有迁移及业务记录，不覆盖
已有 `.env`，也不需要删除数据库卷。

## 第一次打开：账户与模型

1. 启动后，在浏览器访问 `http://127.0.0.1:18080`。首次使用创建本机管理员账户，
   密码至少 10 位；以后使用此账户登录。
2. 点击左下角 **模型设置**，填写 DeepSeek API Key。默认推荐 `deepseek-flash`，
   也可选择 `deepseek-v4-pro`。已有的有效模型配置会保留。
3. 确认模型使用许可并保存。保存后立即用于后续轮次，无需修改模型环境变量或重启。
   密钥不会回显；以后留空代表保留原值。
4. **本地项目不需要 GitHub Token**。只有使用 GitHub 分析或显式启用固定仓库的
   GitHub 只读工具时，才需要相应只读凭据。

若旧配置为已退役的 `deepseek-chat` / `deepseek-reasoner`，页面会提示更新，要求
选择在用模型并显式保存，不会沿用旧模型发起调用。模型可用状态表示配置与许可
满足本地检查；供应商密钥、账户额度和实际响应仍以真实请求结果为准。

## 上下文窗口与累计额度

模型设置中的 **上下文窗口与压缩** 可选择自动跟随已声明的模型API窗口，或设置
不超过该能力的自定义窗口。默认在本轮可用输入空间的65%开始压缩、85%强制压缩，
目标为50%；输出、协议空间和剩余累计Token额度也会参与计算。必要的目标、权限、
未完成事项、证据引用与最新完整工具交互不会为了达到目标比例而删除。

单次上下文窗口和累计Token预算是两件事：压缩减少后续重复发送的内容，不能恢复
已经消耗的Token，也不会增加费用或调用额度。设置对后续轮次生效，已开始的轮次
使用其冻结配置。原先“上下文预算已用尽”的提示现按累计输入、累计总Token或窗口
不足分别说明。升级后需要重启后端并刷新网页；本次上下文修复不新增数据库迁移。

GitHub分析的“累计用量限制”还可选择 **按费用控制** 或 **手动累计Token上限**。
按费用模式沿原美元账本逐次预占，同时保留10000000 Token安全顶；手动模式则在
美元上限之外执行填写的Token上限。旧设置如60000会明确显示为手动模式；需要切换
时选择按费用模式、保留所需美元上限并保存，下一轮生效，原Run额度与历史费用保留。
每轮结果同时显示累计Token与账本费用，Token不足不代表美元费用已经耗尽。

窄屏顶部把导航和模式选择分成两行；点击菜单打开历史后，可用关闭按钮或Escape
收起侧栏。项目选择、打开项目和项目权限仍位于对话上方。

## 打开项目并设置一次权限

1. 点击 **打开项目**，输入运行 Harness 的这台机器上的项目绝对路径，例如
   `/home/developer/my-project`。WSL 服务使用 Linux 路径；网页不能凭客户端路径读取
   另一台电脑的磁盘。
2. 点击 **项目权限**。默认本次授权总预算为 **US$0.25、最多 64 次模型调用、30 天**。
   费用和调用额度由这个项目的各轮、各会话共享；每次发送消息不会重新获得额度。
3. 阅读隔离编辑、命令执行和模型内容处理范围后，点击 **授权此项目并保存**。
   日常授权范围内的读写和执行不需要逐次勾选确认。
4. 可选的 GitHub 只读工具默认关闭。显式启用后只读取此仓库固定提交的文件，
   不允许发布消息、提交 PR 或其他远程写入。

授权过期、撤销或预算用尽时，需要本人显式重新授权，系统不会自动续期或增加额度。
重新保存项目权限会创建新的授权版本，不清除旧费用与历史记录。管理接口也可通过
`DELETE /api/v3/agent/projects/{project_id}/authorization` 显式撤销项目许可；
该写请求继续受登录、同源和 CSRF 校验约束。项目选择与 **打开项目** 始终可用；
切换项目会开始新的对话，已有会话仍保留在左侧历史中。

## 日常使用：直接描述需求

在输入框写目标，例如：

> 修复 add 的加法错误，并补充回归测试。

也可以从调查或新项目开始：

> 梳理这个项目的架构，指出入口和关键模块，并给出源码依据。
>
> 创建一个带独立 CSS 和 JavaScript 的静态页面。

按 Enter 发送，Shift+Enter 换行。助手会读取项目、安排步骤、调用获准工具并验证
结果。调查任务展示公开回答与源码依据；页面不展示模型内部推理。

执行中输入框保持可编辑，可以直接补充要求，也可回答助手提出的问题；补充指示
会在安全点处理。同一个按钮在有文字时发送，空框时中止。停止请求的接收与执行器
实际停止是两件事，已发生的用量仍按回执核算。历史暂停记录仍可继续。

GitHub分析模式也使用同一个发送/中止按钮：运行中输入文字可提交补充，清空输入后
点击 **中止** 停止本轮。加载区域展示实际工具读取、重规划与核验进度。新增的补充
消息会保存到PG并显示已接收/已纳入；已发送的旧模型请求保持不变，后续安全点应用。
助手确实缺少信息时显示具体问题并等待，直接在原框回答即可继续原Run/checkpoint，
不重新创建任务或增加额度。等待时空框同样可中止。历史未完成报告的追问仍沿原
Thread建立新轮次，保留原证据和公开上下文。
若原调用仍在结束，会保留输入并等待回执；确认后再发送即可，原费用不会回退。
历史暂停记录可使用同一按钮继续执行，不再额外展示暂停/取消按钮。

## 从 GitHub 调查到修复和 PR

在GitHub分析中描述目标，例如“找出仓库可能存在的错误并提出PR”。调查连续空搜索
或重复读取时会先切换到目录、依赖声明、测试与其他源码路径，不能把空搜索当作
仓库没有问题。可核实缺口需要你提供信息时，会保留任务等待回答。系统不能保证
任意仓库必有缺陷，也不会为了生成PR虚构问题。

1. 在当前分析中点击 **在隔离工作区修复并准备 PR**。服务器按页面固定的仓库与
   commit建立项目副本，随后进入项目助手。该操作不自动授予模型、命令或发布权限。
2. 在 **项目权限** 中设置隔离修改和模型预算，准备页面提示的固定运行环境，输入
   修复需求。助手复用Harness读写与测试；缺少依赖或镜像时按环境提示处理。
3. 修改完成且当前代码树的实际测试、核验通过后，打开 **GitHub 变更交付**，
   核对目标分支、标题、说明、完整Diff与测试结果，生成固定提案。
4. 本机部署还需独立的 `MGAR_V3_GITHUB_WRITE_TOKEN` 与
   `MGAR_V3_ALLOW_EXTERNAL_WRITE=1`；在服务器 `.env` 配置后重启服务。
   网页模型设置里的GitHub Token继续用于读取，不会被自动提升为发布凭据。
5. 在交付界面给当前项目设置发布许可，再明确批准该完整提案，系统通过持久
   Action/Outbox创建Draft PR。许可不代替提案审批，也不增加模型预算。
6. 完成GitHub审查、将Draft转为可合并状态并通过CI后，刷新 **合并检查**。
   只有单独授予合并许可，并准确确认当前PR/head/目标版本，才会排队合并。
   新提交、目标分支变化或未通过的检查需要重新审查与必要的重测。

关闭页面后交付记录仍可恢复。远端响应丢失时先 **核对远端回执**；只有能证明
已发送步骤实际完成，才可明确继续尚未发送的后续步骤。查不到不代表没发生，
未知请求不自动重发。发布、合并和模型用量的未知结果分别保留，不伪造成功或退款。

当前直接发布支持普通文本的新增与修改，最多16个文件、128 KiB Diff；删除、二进制、
空文件或超限变更可从任务结果下载补丁后另行审查。源码快照不完整、原项目有未提交
变更或测试未覆盖当前树时，不会将其标为可发布。

上述链路的工程检查使用真实PG、隔离执行与受控GitHub端点；真实供应商质量、
真实GitHub发布/合并结果须单列，不能用工程通过代替。实现边界及验收见
[持续协作与交付任务](harness-v4/ANALYSIS_COLLABORATION_DELIVERY_TASK.md)。

如果上一轮用量回执缺失，原费用预占和失败记录会保留，但你仍可在原页继续追问，
沿用已有证据、任务与公开草稿。每条新消息单独执行，不自动重发旧请求；页总费用、
Token和调用额度会扣除所有历史用量及未决预占，不会因换轮次重置。界面会区分真正
仍在结束的调用，活动轮次仍串行。自动分析会复用本会话已授权的固定版本源码，
重叠范围不算新的调查进展。升级后若旧页面出现空节点或脚本版本提示，按
`Ctrl+Shift+R`强制刷新一次；新版页面会为脚本与样式自动使用内容版本URL。

完成后继续在同一输入框说“再补一个回归测试”或“调整这个页面”，下一轮会沿用
同一会话与累计工作区。左侧可切换历史，刷新后恢复所选会话。重复提交按请求标识
去重；配置或环境问题应处理后再发送，用量或副作用未知时不会盲目重发。

## 环境准备与阻塞提示

项目就绪检查会核对项目结构、固定镜像及运行工具；无法执行的依赖、命令或运行时
会显示具体阻塞信息。环境检查不等于任务测试通过，缺包也不能标成代码已验证。

在 **项目权限 → 项目运行环境** 的高级设置中，可以选择 Harness 所在机器上已
准备的镜像锁定文件。默认基础运行时为 `.local/r03/sandbox-lock.json` 对应的固定
镜像；镜像不存在时需要先准备，不能只填写一个镜像名称。开发者构建基础运行时的
入口为 `uv run python scripts/build_r03_sandbox.py`，它会实际执行 Docker 构建并
生成锁定文件；生产或自定义工具链应使用经核对的准备结果。

Python 项目还可提供受控的离线 wheelhouse 目录。准备过程要求依赖哈希校验，并在
隔离环境安装受信的 wheel；不会在任务执行阶段任意联网下载或运行包安装脚本。
不满足离线准备条件时，保留原因并等待补齐。不同语言、系统包和私有依赖仍需匹配
的已准备运行环境，不能把高级设置视为任意项目均已自动装好的承诺。

## 审查结果与应用变更

文件先在隔离副本中修改，原项目不会随模型编辑立即改变。完成后可以查看文件清单、
命令与验证记录、完整 Diff，并下载补丁。

点击最新一轮的 **应用变更到项目** 才会写回原项目。回写会校验审查的代码树和
原文件前像；原文件已被其他操作修改时返回冲突，不覆盖这些变化。相同请求再次
执行会返回已记录的回执；中断且结果未知时需要核对，不按成功处理或盲目重写。

没有行为测试的项目可能仅完成构建或内容检查。页面会明确显示
**“仅构建/内容检查；未运行行为测试”**，结果记录为 `verification_scope=build_only`
及 `tests.status=not_run`。这可以交付可审查产物，不代表行为测试通过。实际执行过
测试的任务另行展示真实测试数和结果。

## 应用预览

当前轮完成后可点击 **启动应用预览**。预览通过固定运行时启动项目进程，经受限的
短期访问能力在页面内显示；相对路径的 HTML、CSS 和 JavaScript 已有真实浏览器
验证。点击 **停止预览** 会停止对应进程，旧预览访问能力随后失效。

项目页面运行在不共享控制页面来源的沙箱中，不能读取父页面或控制 API；预览能力
只允许读取对应预览的资源，不授予主机文件、控制接口或写入权限。不要把预览地址
当成公开部署地址。

当前能力是受控 HTTP 预览。完整 HMR、WebSocket、任意根绝对资源路径和复杂开发
服务器代理尚未承诺支持；需要这些行为的项目应按实际回执处理，不能仅因进程启动
就宣称应用交互全部验证通过。

## 旧模式：GitHub 仓库分析

以下说明适用于顶部的 **GitHub 分析** 模式。该模式读取固定 GitHub 仓库并生成
带证据的只读报告；其仓库 URL、分析范围及分析许可表单不属于默认项目助手的
日常任务提交步骤。

### 进入 GitHub 分析模式

1. 浏览器访问 `http://127.0.0.1:18080`，使用本机管理员账户登录；新安装先按上文创建账户。
2. 切换顶部的 **GitHub 分析**。刷新页面仍会保留有效登录会话。
3. 点击左下角“模型设置”，填写 DeepSeek API Key、在用模型名称和 GitHub 只读 Token。
4. 选择允许分析的仓库范围、每次分析的费用上限和使用许可有效期。
5. 高级选项可调整每次分析的 Token 总预算，默认 500,000。
6. 确认模型使用许可并保存，设置立即生效，无需重启。GitHub 分析遵守本节的仓库范围与预算。

本功能是单个本机实例的管理员账户，不提供开放注册或多租户账号隔离。
首个账户只能从运行服务的电脑创建。已有 CLI 和旧操作员接口继续兼容原 token。

### 提交问题与追问

在首页填写 GitHub 仓库 URL 和问题，例如：

> https://github.com/pallets/flask
>
> 说明请求如何进入应用，指出入口文件和关键调用关系。

点击“开始分析”或按 Enter 发送，Shift+Enter 换行。中文输入法选词时的 Enter 不会
误发送。Agent 在预算内循环搜索和阅读源码，页面
实时显示执行阶段、工具活动和逐步生成的报告草稿。草稿标记为“尚未核验”，完成
核验后显示正式报告和引用。完成后在同一输入框追问，沿用固定仓库、Commit、
上一轮报告与证据映射。左侧可切换历史对话，刷新后可恢复所选对话。

模型供应商到后端、后端到浏览器均使用流式传输；浏览器断线后按事件游标重新连接，
刷新页面也会恢复已生成的草稿。页面只显示报告正文和执行阶段，不展示模型内部推理。

缺少模型配置或使用许可过期时，页面直接打开设置弹窗，并保留已填写的问题和 URL。
补齐后点击“保存并开始分析”，即可继续原来的提交。左下角也可随时打开模型设置，
或退出登录。已保存的密钥不会回显，留空代表保留原值。

### 自动分析与验收

无需指定模型轮数、工具次数或重试次数。网页保存的新许可使用自动执行策略：
在 Token、费用和时限内持续调查，形成候选报告后先逐字核验源码引用，再独立调用
模型检查是否回答了用户的问题。缺失项会反馈给 Agent，促使它继续阅读或修订；
获得新信息后，防循环计数重置，不因累计核验次数而停止。

后台会复用重复读取的证据，并防止连续空搜索、无新增信息的调查、反复提交未改进
的答案形成死循环。已明确失败的连接、限流和格式错误会按有界策略处理，用户无需
配置 retry count。调用中断且无法确认用量时保留预算预占，不自动重发付费请求。

Token 总预算包含供应商实际报告的输入与输出；每次请求重新发送的历史上下文也计入
输入。请求前先预占保守上界，收到完整用量回执后释放差额。费用预算和一小时时限
仍是执行边界。预算不足、缺少证据或无法继续取得进展时，保留部分报告并明确标记
未完成，不把它当成已验收的答案。独立模型核验不能保证语义正确或替代人工判断。

从旧版本升级后，在“模型与使用设置”保存一次即可启用自动策略；密钥留空会保留。
旧文件许可和历史任务的固定次数上限继续有效，不会被自动放宽。

### 配置与许可

- 设置保存在 PostgreSQL，服务读取最新配置，重启后仍有效。
- 密码使用 scrypt 哈希保存；登录使用 HttpOnly / SameSite Cookie，写请求校验 CSRF。
- 模型和 GitHub 凭据使用本机密钥加密保存。备份时应同时备份 PostgreSQL 和
  `.local/web/credentials.key`；单独恢复数据库不能解密凭据。
- 本节的模型许可确认与保存操作会记录分析许可、范围、预算、有效期和管理员。
  它不会启用 GitHub 写入、自动批准补丁或发布 PR。
- 费用上限按应用的预算核算规则执行，统计值不代表供应商的精确账单。
- 有真实分析排队或执行时不能修改配置；可先暂停。更换许可后，旧运行不能借用新许可
  恢复。已结束对话可以直接追问：新一轮使用当前有效许可、模型和预算，保留原仓库、
  Commit、上一轮报告与证据，不受旧任务缺少 Token 总预算的影响。撤权、过期或仓库
  不在当前范围内仍会拒绝执行。
- 已有 `.env` 与授权文件仍作为兼容配置读取；在网页保存后，网页配置优先。

### 开发和验证

在模型设置的“开发与离线验证”中可显式选择合成样例。演示不会读取所填仓库，
不会调用模型，页面始终标注演示。旧业务、修复与审批页面保留在 `/legacy` 和
`/legacy/workbench`。

工程验收命令：`make verify TASK=AGENT-UI`。测试使用真实 PostgreSQL、Redis、
LangGraph checkpoint、模型客户端和预算账本。GitHub/模型响应由测试控制，不产生
真实付费调用。浏览器验证包含创建账户、登录、缺配置弹窗、保存后自动提交 live
分析、超出旧轮数限制的调查、验收反馈、Token 并发预占、供应商 SSE、浏览器流式草稿、
断线/刷新恢复、持续追问、退出和手机布局。真实外部调用需要用户提供有效凭据。
