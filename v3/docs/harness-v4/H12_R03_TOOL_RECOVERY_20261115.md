## 修复后的行为

原循环会在预检路径拒绝、工具denied等情况下直接结束任务，还可能把底层异常中的
宿主路径原样交给模型。现在新任务使用冻结的ToolErrorPolicy及八类结构化错误回执：

- 宿主绝对路径、遍历和编码变体继续拒绝；只提示TaskGrant与当前Lease交集中的
  工作区相对根。合法新调用仍通过原Broker；没有新增读写、命令、网络或凭据能力。
- 参数错误默认允许首次拒绝后的3次纠正，可信配置范围0–8。回执记录剩余次数；
  更换工具、换路径、一次成功或重启均不能重置。耗尽后保留BLOCKED及待补充信息。
- 固定命令错误提示已授权command ID；合法分页错误提供当前已颁发路径/hash的
  retry/next参数。外来hash、来源、Lease、epoch及符号链接逃逸继续阻断。
- 预检拒绝也使用原额度、operation journal、RecoveryIO和CAS。拒绝与成功后续调用
  有独立operation ID及审计关联；已知拒绝恢复复用，未知结果不盲重发。
- 缺失能力进入既有Ask/inbox。文字“批准”不修改TaskGrant、Lease或冻结验收范围，
  当前任务保持BLOCKED；取消沿用原token。另修复了PG已存在待答问题、状态接口却
  仍显示running的投影问题，以及待补充信息未投影进checkpoint的问题。
- 模型只收到安全模板、相对范围和声明参数约束。原底层诊断最多16000字符保存至
  私有CAS，不能凭hash通过artifact_page读取。真实已执行测试保留原失败日志及回执。

R02仍在工具执行前拒绝整批Schema错误。R03给该原模型operation补充安全参数提示，
不伪造工具执行记录。其余已组装工具拒绝使用R03计数。原无进展检测仍逐批运行，
可纠正错误仅获得有界机会，不被记为进展；正常重复读取仍会被守卫阻断。

协议和边界详见[Tool Error Taxonomy](TOOL_ERROR_TAXONOMY.md)，回执结构见
[JSON Schema](../../config/harness_tool_error_receipt.schema.json)。
