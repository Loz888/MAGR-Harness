## 两阶段规则

| 类型 | 原始树 Baseline | 原 Engine 封存后的 Final |
|---|---|---|
| bugfix | 执行完整既有行为矩阵和单独目标计划；目标必须是实际断言红，原有失败保留身份 | 目标绿、完整公开回归无新增失败、独立 Judge 绿及其余必需维度通过 |
| feature | 既有行为绿；新目标可绿、断言红或精确声明的目标符号缺失 | 新目标实际执行并绿；既有行为、独立 Judge 及完整性均通过 |
| refactor | 只检查既有公开行为，不检查新结构，不运行最终私有 Judge | 既有行为等价、公开声明结构及独立 Judge 都通过 |
| run_app | 只检查既有行为；不要求新服务已启动 | 继承 R04 的固定启动入口、Ready、实际 HTTP、端口/进程清理，以及公开回归和 Judge |

`TaskBaselinePolicy` 冻结公开要求、R01 内容派生 ID、benchmark_revision、既有行为
计划、目标计划和可选结构规格。独立基线保存在 CAS，引用真实命令、镜像、日志和
测试身份；`BaselineAssessment` 只能解释这些证据，不能改写原始测试结果。

Feature 的预期编译红当前只支持 Go 的明确诊断：必须同时匹配公开声明的符号名、
接收者和目标引用文件，每条诊断都匹配；命令已知退出 1、日志完整。依赖、语法、
非目标符号、错误文件或混合错误仍 BLOCKED。其他语言使用公开断言探针，尚无
精确诊断适配器的编译/导入失败保持受阻，不能根据错误字符串猜测放行。

预期缺失 API 的 `target_observation=DECLARED_TARGET_MISSING` 可以使**类型基线**
PASS；原测试回执仍保留未解析/编译失败状态，测试数量和新增回归数不能伪造为 0。
最终目标缺失仍失败。Bugfix 的原目标已绿则阻断，因为它没有复现所声称的缺陷。

既有矩阵必须来自公开冻结的完整旧行为范围，不能为了通过而缩小。新增 API 测试
单独放入目标计划：不能把一个必然引用未实现 API 的新测试混入“原有行为必须绿”
再宣称环境坏了。实际题集采用此规则时须公开拆分命令、复核所有旧测试覆盖并重新
冻结；原 24 题不会因启用新代码自动获得新分数。

## 冻结前审查与断言追溯

`JudgeTraceabilityManifest` 为每条真实断言记录 `assertion_id`、
`acceptance_requirement_id`、源码路径/行列、AST 表达式 hash；绑定所有私有源码
hash、公开要求 hash、基准修订和固定执行命令 hash。当前清单适配器支持显式
Python pytest 源码，盘点 `assert`、异常断言/抛出、unittest/pytest 断言调用。

审查同时检查：实际断言全部且仅出现一次；每条绑定已公开要求；每个非生命周期
要求至少有断言覆盖；行列/表达式/全部源码未变化；约束中的具体符号名确实公开。
生命周期由 R04 独立证明，不能虚构一条私有断言替代。

执行审查只接受固定 pytest 入口、已审查的文件和有限展示参数。`-k`、`-m`、忽略
文件、伪造成功输出、遗漏文件和命令改变均拒绝。仅盘点清单时可以没有命令 hash；
冻结或真实执行时必须绑定命令，静态盘点结果不能冒充执行审查 PASS。

`EvaluationRunner.initialize()` 在创建实验/分配任务前审查；派发前和最终 Judge
再次核对。开发题也显式绑定版本化私有 registry 的 hash，避免退回旧内置 Judge。
最终 Scorer 从原 PG 结果引用重读 CAS，验证清单 hash、源码 hash、实际命令和
作用域，不接受调用方自报 PASS。缺失清单、基线或结构证据时阻断且保留 null 计数。

这是一套有明确支持边界的清单和一致性检查，并不能自动证明所有自然语言语义。
基准负责人仍须审查每条断言与公开要求的实质关系；动态/外部 Judge 不能用一个
没有断言的 Python 启动器冒充已审查。其他语言的私有判定需另建可审核的完整清单
适配器。在此之前保持受阻；不得给空清单补一个假映射。

私有 registry、路径、源码和断言内容留在控制器/Judge 侧，不传入模型上下文。
模型只接收公开要求、公开探针及工具反馈；profile 只携带私有绑定的不透明 hash。
证据中的合成示例来自公开测试夹具，不是新的独立持出答案。

## 单一 helper 的结构检查

`SharedHelperSpec` 公开路径、语言、调用方、目标要求 ID；仅当名字在公开要求中
逐字出现时才允许 `required_name`。没有名字要求时，`_lowerkey`、其他类方法或
模块函数均可接受；不能额外要求 `_canonical_key`。

固定公开 AST 程序检查共同 helper 的**返回值是否进入实际使用位置**，并与独立
行为矩阵同时验收。Python 检查声明类的映射键访问；Go 使用标准库 `go/parser`
检查声明调用方的返回值路径。支持直接调用、局部别名和返回值别名；无用 helper、
丢弃返回值、各用各的 helper、调用方仍各自转换再套 identity 均不能通过。
类重绑定或方法替换不能借同名 AST 伪装实现。改变 Unicode 等旧行为时，即使结构
通过，独立公开回归仍会失败。

探针不导入或执行被测项目；Go 仅编译运行固定的检查器自身。程序和公开规格一起
按内容寻址，继续通过原 Broker/CommandSession 的只读工作区、隔离镜像、资源、
网络和 CAS 边界执行。自有 Go 检查器以 `-p=1`、`GOMAXPROCS=2` 控制并行度。
解析失败、资源问题、超时、残缺帧以及适配器不支持的动态调用方控制流均 BLOCKED，
不会把无法判断归为结构 PASS；错误反馈保留有界原因，原始日志仍在 CAS。

该适配器不是任意程序的通用数据流证明器。复杂控制流、其他语言或不同结构要求
需要新的公开适配器并重新冻结；不能仅为了完成某题绕过结构证明。当前合成 Go
