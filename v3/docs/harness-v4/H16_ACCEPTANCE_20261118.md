# H16 本地工程验收

2026-11-18，H16 在源码 `ec02dbf` 上通过 **13 项**。同源码上 H13 通过 42 项，H14 通过 181 项，H15 通过 19 项。四个验收均为零失败、错误和跳过。Ruff、mypy 和两份界面脚本语法检查通过。[机器验收记录](accept/HV4-H16/accept.json)

## 服务端排队

两个项目共提交六个任务。全局 Worker 并发为 2，每个项目上限为 1。首批两个任务同时占用运行槽，剩余四个任务在持久队列中等待。整体耗时 19.40 秒，六个任务的派发等待分别为 127 ms, 173 ms, 5572 ms, 6576 ms, 8208 ms, 9133 ms。中位等待 6.07 秒。这是受控本机负载记录。

## 验收覆盖

| 范围 | 实测结果 |
| --- | --- |
| 两项目三成员 | 成员只列出已分配项目。跨项目与同项目不同成员的会话、结果、补丁、事件、命令日志、控制接口均被拒绝。成员可下载自己任务回执中的日志。全局 CAS 仍仅限管理员。 |
| 工作区边界 | 原实现允许嵌套目录加入项目隔离，已保留复现。最终源码拒绝重叠项目目录及 Harness 服务数据目录进入受管理范围。 |
| 成员撤销 | 新访问及进行中的 SSE 流失效。再次授予成员权限生成新绑定。注入发生在模型预占与派发之间的撤权时，实际请求数和遗留预占均为 0。 |
| 独立凭据与预算 | 两个受管理项目分别通过各自的模型凭据取得受控应答。一个项目耗尽次数后，另一项目仍可执行。清空项目 Key 会关闭该项目的模型调用。 |
| 配额与公平派发 | 同项目正在运行和等待入队额度分别受限。排满的项目返回 429；另一个项目有空闲槽时仍能执行。 |
| 控制器竞争与恢复 | 第二个 PostgreSQL Engine 会话无法取得写锁。未派发任务、持久暂停任务和已有模型回执的任务均可由新控制器接管，同一 Run 继续使用，已结算的模型请求只发出一次。 |
| 分离进程 | 独立 HTTP 前台通过真实 Unix socket 连接控制器，前台进程只持有 socket 地址。测试覆盖 Cookie 隔离、伪造转发头剥离、SSE 撤权以及控制器离线时的 503。 |
| 旧库升级 | 在真实 PostgreSQL 中从 H15 schema 追加 `0057`。既有管理员、浏览器登录会话、产品对话、单管理员唯一性和旧迁移哈希通过复验。 |
| Runner 与产品回归 | H15 仍以设备票据运行原固定测试；H13 和 H14 的会话、项目入口及插件回归使用同一源码。 |
