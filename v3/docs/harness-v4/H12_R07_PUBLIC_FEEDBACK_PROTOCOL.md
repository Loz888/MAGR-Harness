# H12-R07：公开测试反馈与进展检测协议

版本：`harness-public-feedback-v1` / `harness-public-test-feedback-v1`。
本协议是 R07 工程能力，不代表 H12 真实 Agent 质量通过。

## 启用和冻结

`EvaluationProfile.public_feedback_policy` 显式启用新策略；默认 None，旧 profile、
TaskPlan、回执和 WorkingState 省略新增字段，原实验配置和历史分数不改。
评测 Runner 的 `public_feedback_policy` 参数还要求绑定 R06 审查过的新基准修订。
冻结配置保存策略、目标探针、静态命令、完整公开回归计划及对应公开契约。
恢复时策略或冻结 profile 不一致即拒绝，不能借恢复增加额度或替换检查范围。

启用条件包括 R01 contract-v1、已冻结的 public-probe-v1，以及非空、已配置报告器
的完整公开回归计划。目前额外回归最多 8 条，cwd 必须为项目根目录，执行器必须
属于原目标/静态/公开探针已经批准的程序集合；不支持的配置在冻结前阻断。
不增加 Shell、网络、文件或凭据权限，原 Engine、PG、Broker 和授权算法继续负责。

固定命令 ID 为已配置的 `build`、`tests`、`public_probe` 和 `regression_N`。
ToolSpec 显示精确 ID/argv；回归 ID 来自冻结的完整计划，同 argv 只调度一次。
额外回归不接受模型自行提供的 argv；未许可命令仍交给 R03 安全纠错/拒绝机制。
未配置的静态检查不猜测命令、不补写静态 PASS；后续实际题集应公开声明适用检查。

## 每次修改后的执行

每个成功 apply_edits 后，沿原 run_tests 工具通道检查当前树尚缺的静态、目标、
公开行为探针和完整公开回归。按顺序执行，即使某项断言失败也采集后续已冻结检查；
取消、真实权限拒绝、未知执行、原工具/时间预算耗尽等仍按原规则停止。
每次检查计入原 Run 工具预算；单次超时还收紧到当时的剩余时间，不另建免费额度。

同一模型回复包含两次编辑时，两棵树分别检查，不能只验证最后一棵树。内部检查
不伪造供应商发出的 tool call：原模型批次的全部 tool 回复保持连续；随后以明确的
自动公开观察消息反馈，避免破坏模型 API 的工具消息协议。

复用条件是同一 Run、相同树、相同固定命令/用途、相同任务语义及已确认的完整日志。
新树不能用旧树的绿回执，旧任务目标也不能冒充新目标的检查。检查只是观察，不是
整个自然语言目标完成的证明；合格最终答复、R04/R05/R06 及独立 Judge 仍是必要门。

恢复不能只看“这次树是否又变了”。编辑已落盘、工具/进程回执已知而循环尚未保存
观察时，从原 PG/journal 恢复相同操作 ID 和回执，补回观察；不再次执行已知命令。
只确认进程、外层工具尚未完成时，沿原 reconcile 和日志恢复规则补齐反馈。
未确认执行保持未知，不能据此盲重发。

## 反馈 Contract

每份 PublicTestFeedback 绑定 task、Run、workspace、执行 epoch、公开修订、
requirements hash、任务语义 hash、实际树、命令 ID/argv、原 receipt ID、退出码、
原始日志 hash 和 CAS artifact hash。任务语义 hash 排除 fencing epoch，允许合法
恢复沿用同一次真实执行；目标、要求和权限范围等变化不会复用成相同任务语义。

内容包括实际失败 ID、断言摘要、真实测试/失败/跳过数量及明确的 outcome/category。
展示最多 16 个失败 ID，每个 256 字符；长名称附内容 hash 并标记截断，摘要最多
4000 字符。完整输出通过已签发、作用域约束的日志引用读取，不能用 hash 自行授权。
`log_complete` 仅表示日志完整，不等于测试范围/测试身份已完整证明。

额外公开回归与 R05 使用同一冻结报告器和解析器，支持 pytest、unittest、Go JSON、
Mocha JSON 和 TAP；普通目标沿原命令/公开探针验证。仅凭退出 0 不报绿。编译阻塞、
残缺报告、未执行、哈希/树不匹配和未知执行保留 unverified/null；skip 保留实际数量，
不能当成成功断言。最终摘要也再次核对结果树，旧树通过不能展示为新补丁通过。

unittest 的测试名与终态之间可以插入真实 stdout/stderr，例如 argparse 打印 usage
后另起一行 ERROR。解析器保留该测试身份，再验证终态、完整数量、唯一身份及退出码；
孤立终态、未完成测试或数量矛盾仍阻断。旧原始日志、回执和 score 不重写。

反馈类别区分公开绿、公开断言失败、公开检查错误和未核实观察；它们不是对模型或
环境的自动归责。报告须另列“协议是否正常送达”“公开行为是否满足”“真实模型是否
通过”，不能把受控夹具里的成功当作模型能力提升或真实 Agent 门通过。

## 当前状态和重复检测

`WorkingState.public_test_feedback` 固定保存当前树、当前任务语义下每个命令最新
观察，避免历史压缩时丢失真实失败；旧树观察不进入这个当前状态。日志正文留在 CAS。
原有 acceptance checklist 继续单独表示尚未满足的目标，公开测试绿不能替代整个目标。

失败签名依据结果、退出码、数量、失败 ID 和有界断言上下文；耗时、UUID、地址等
常见运行差异不算新进展，日志原 hash 仍原样保存。进展键再绑定树和实际 argv。
同树/同命令/同失败的重复不因新 receipt ID、操作 ID 或新日志 hash 而重置检测。
新源码/日志页、新失败证据和新树可推进；往返补丁、重复读取和重复空查询受原检测约束。

R07 默认连续 3 个无进展工具批次停止，冻结范围为 2–6；第一次无进展先给出纠正
方向，原阈值 None 的旧任务仍用旧策略。计数与 seen receipts/trees 在 checkpoint 中
保存，恢复不清零。预算始终是最后边界，不允许靠变化的错误文本无限重试。

公开规格确有歧义时使用原 ask_user 等待澄清，再沿用同一 Run、记忆和剩余额度。
回答不是新的工具、写入或发布授权；未完成的等待不能记为成功。

## 私有信息边界与公开矩阵

Worker 反馈只来自已批准的公开命令与公开探针。私有 Judge 源码、断言、答案和
最终判定不进入后续 Worker 请求；独立 Judge 在最终门执行，不反向用于改提示。
即使知道私有 CAS hash，未签发引用仍被 artifact_page 拒绝。

[开发公开边界矩阵](H12_R07_PUBLIC_BOUNDARY_MATRIX.md)及
[版本化配置](../../config/h12-r07-public-boundaries.json)覆盖 unknown remaining argv、
quoted delimiter、模块入口导入、readiness、清理、轻量导入，跨 Python/Node/Go 的
5 个公开合成项目，每类均真实执行正反例。它们是工程开发补充集，不是重新冻结的
原 24 题，也不是新的独立持出；R08 仍须绑定实际项目接口、公开计划和全新持出。

实际 Schema 位于 [protocol/r07/](protocol/r07/README.md)。完整工程记录保存源码
commit/fingerprint、原 PG/CAS、命令/日志、失败历史和只读账本核验。R07 完成后停止；
工程 PASS 不等于真实 Agent PASS，原 H12 FAIL 与 MVP 未放行状态保留。
