## 委派契约

- 主 Agent 通过 `consult_repository_expert` 提交一个具体问题和至多三个仓库相对路径。每个 Run 最多两次不同委派，同一任务目标、工作树、问题和文件集合可重用已结算结果。
- 专家沿用主 Run 的项目身份、凭据和模型，每个文件只向专家提供至多 3072 字节的片段。工作树、读授权和路径在读取及返回时验核。符号链接、保护文件和授权范围外的目标会被拒绝。
- 专家调用模型一次，最多生成 768 Token。专家没有工具，结果只进入主 Agent 的工具反馈。主 Agent 亲自读取证据、执行写入与测试。写入继续通过原有工作树锁和文件摘要校验。
- 每次专家调用进入同一 PostgreSQL Run 和原有项目账本。主 Agent 与专家共同消耗模型次数、费用和累计 Token。系统以保守的单次输入和输出上界检查剩余额度，以供应商确认的用量结算。未知结果持续保留预占，等待核账，恢复时复用已知结果。
- 委派在父流程内同步执行。父任务取消、过期或撤权会传播。专家采用 30 秒协作式期限，HTTP 每次空闲等待上限为 12 秒。流中途停止且缺少有效用量时按原账本处理。

## 本地试用

默认是单 Agent。受控试用时，在执行 Harness Run 的服务环境中设置下列配置，重启该服务并创建新一轮产品会话。多用户部署在内部控制器上配置。仍使用现有项目授权与模型设置。网页会话仍以自然语言提交需求。

```dotenv
MGAR_V3_HARNESS_EXPERTS_ENABLED=true
MGAR_V3_HARNESS_EXPERT_TOKEN_LIMIT=200000
```

第二项是每个启用委派的 Run 的累计模型 Token 上限，支持 4096 至 10,000,000。主 Agent 会按任务需要决定是否委派。例如，提交「先核对 README 和入口文件是否一致，再总结项目结构」。试用结束后将第一项设为 `false`，重启服务。
