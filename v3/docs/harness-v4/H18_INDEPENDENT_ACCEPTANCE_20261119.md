## 恢复失败后原目标无法重试

对已校验的正常快照，在隔离空库上执行恢复，并让进程的 PATH 暂时找不到 `pg_restore`。CLI 返回 `SNAPSHOT_POSTGRES_CLIENT_MISSING`。目标数据库仍为空，但指定的新运行目录已经存在。恢复正确 PATH，保持源快照、目标库和目标目录不变，CLI 返回 `SNAPSHOT_DESTINATION_EXISTS`。改用一个新的运行目录后可成功恢复，真实 HTTP 确认原登录有效。诊断按预期识别了缺少工具，失败遗留的目录阻塞了恢复。[实现位置](../../src/mgar_v3/ops/snapshot.py#L204)

修复应在 PostgreSQL 导入事务成功及迁移与 CAS 核验通过后发布运行目录，或使用明确的暂存状态并在失败时清理本次尝试创建的目录。发布失败也应明确记录数据库是否已完成恢复，并提供可重试的收尾动作。修复后仅复测本轮失败的同目标恢复用例，验证修好 `pg_restore` 后原样重试成功，并可用原 Cookie 登录。
