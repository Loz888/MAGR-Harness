# Phase 1 · 安全与恢复修复评测协议

历史基线为 Phase 0 的提交 `fcabf97`。源码提交先于正式采样冻结。工程检查使用单独的临时 PostgreSQL 数据库、测试身份和本地文件系统。真实供应商调用、远程发布及运维环境变更的预算为零。[计划](../PLAN_V1.0.md)

| 评测 | 输入与判定 |
| --- | --- |
| E4 原样本回归 | 使用原 200 条开发回归、标签、生产写入入口和评分器。冻结数据 SHA-256 为 `e409b7f55fc465d1335b8ad787d5b8db6d322eaa615e189dd551ff16fc8be3a8`。逐条记录首次三态决策，再查 PG。确认与并发版本测试单列。 |
| E4-R1 独立盲测 | 原样本与新盲测分开评分。独立方在候选交付前封存 372 条输入、标签和评分规则，承诺 SHA-256 为 `24f068bfb773a405a7fedcc6a24e56ebf06f56cb718d9f26735d028f524c1f3f`。敏感样本全部拦截，作用域或来源违规自动确认数为零，自引用不得作为独立证据，高风险过程必须人工确认，来源不足的自述不得自动标记 verified。报告误拒和正常自动写入数。 |
| H18-R1 | 独立方在正式候选前冻结八门协议，SHA-256 为 `e8e78b719e7f149227643689785268c4bbba99dc650e8142753b61518e8d39c0`。在隔离 PG、真实客户端和文件系统上检验工具缺失、导入中断、迁移失败、CAS 不符、发布权限、启动失败、同目标重复恢复及原身份与配置。失败后保持快照、数据库、运行路径和选项一致。 |
| 基础隔离 | 复查受控沙箱的宿主文件与凭据隔离、网络拒绝、超时清理和路径限制。用实际 PG 验证撤权、跨任务读取、跨项目隔离、并发预算预占、未知用量和进程恢复。 |

独立盲测按首次固定候选给出结果，保留失败、未知与未执行项。发现权限泄漏、未知副作用盲重试或错标 verified 即停止该候选。排除试验环境阻塞后可在同一源码定向复检。E4 输入、标签及种子由独立方保管。已评分的持出不能作为后续调参数据。
