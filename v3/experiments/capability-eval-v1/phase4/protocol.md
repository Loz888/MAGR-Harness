# Phase 4 E5-R1 检索性能与复核

产品基线 088b087，使用原 E5 数据生成器、64 条冻结查询、本地 spaCy 向量、BM25 与 RRF。同一算法下对照原实现、两项顺序匹配的作用域索引、索引加 SQL Top-N、再加同一条 SQL 批量明细。排序和授权范围照旧。SQL 先按项目、仓库、操作者、状态、版本及工作记忆有效期过滤，再按原顺序取最多 64 条。全部候选和来源校验仍用原模型及授权条件。新索引只装入专用实验库。

主矩阵含 1K、10K、100K、500K，1、5、10、25、50 并发，四组与 PostgreSQL 冷热两态，共 160 格，每格 192 次。冷指专用容器重启后目标表及索引共享缓冲页为零，主机页缓存沿用宿主实际状态；热指同一格的数据请求预热后观察到目标页。工作线程从计时前取得一个专属只读 PG 连接，全部组复用同一方式，采集窗口内无每次借还连接事件与等待。若连接策略改变，结果不能合并比较。100K 热态 5/50 并发另各做三次 A/D 配对复测，每格 512 次。负载运行期间不同时执行持出评分。

每组执行 EXPLAIN ANALYZE BUFFERS，收集 PostgreSQL 内部执行统计、查询行数等，以及 PG 容器 CPU 与内存。工作阶段拆为权限及候选、证据来源、BM25、Dense、RRF、组装。真实持出和公开开发回归使用 E1-R1 原冻结材料，分别复跑六组检索与原判定器。私有原始记录由库存文件进程读取，只回传汇总及哈希。该样本由原独立方编制，此次为同一冻结持出上的回归复核，运行方与开发方同会话隔离进程。

通过要求为四臂主矩阵完整、有序命中和分数摘要一致、全部请求无 ACL 泄漏或降级、公开及持出结果与旧基线一致。三个 100K 热态 5 并发配对都须观察到完整组 QPS 提升。三个 100K 热态 50 并发配对都须观察到完整组 P99 下降。优先格以三个配对的中位改变量汇报，并保留逐次结果及请求区间。任何 ACL 泄漏立即停止。原 E1-R1 大幅拒答与 Phase 1 写入的失败沿用各自原验收口径。
