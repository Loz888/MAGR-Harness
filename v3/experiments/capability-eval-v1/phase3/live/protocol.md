# Phase 3 正式真实模型协议

用户在确认需要真实模型时要求执行新一轮 Phase 3。两项分别限 H12 256 次与 US$5、H17 1,440 次与 US$24，每试次至多 8 次请求。按供应商峰值且输入全部未命中缓存计算保守上界。真实模型固定 deepseek-flash，启用 thinking，reasoning_effort=max，使用产品 SSE。挂起预占和未确认响应停发且保留，无自动重发。本次只发送合成工作区和实验输入，工作区执行通过原离线沙箱。

H12 用原 8 个合成项目各跑 4 种提案策略。前三组限 2,048 输出 Token，校验 Resume 臂首次读后限 128 Token，以制造真实供应商上限条件，其他轮转回常规上限。模型可选择其实际输出，统计策略遵守率，与成功率分别记录。续写要求检测真实 finish=length、查对合法 CAS、同 Run 和已执行的工具。工程轮已验证控制器丢失后重建，本轮真实样本验证原 Run 的有界模型续写。无效补丁执行、错误跨树续写和更改测试为硬失败。环境预检使用本地既有零模型结果。

H17 使用 30 道合成任务和 3 个固定的输入/执行顺序种子，共 90 对。每对同一来源字节、目标、模型、调用上限、Token 与费用上限。只在委派臂提供只读专家；专家是否调用由模型决定。配对以可用性为处理，低采用率仍落在原臂。绝不把未采样期望和正确答案写入请求输入。判定器用独立模块，从预注册目标、原测试字节、最终源码和产品验证回执重新判定，无模型评分。独立操作者复核另记状态。

预注册优效要求成功率差的 95% 任务聚类配对区间下界大于零，且点估计至少 2/30。非劣界值为 −5 个百分点。启用委派默认还要求保守费用增加不超过 25%，中位墙钟增加不超过 20%，零越权或重复执行。模型错误、预算耗尽、无效输出计 FAIL，环境门导致未发或账本硬停止的未运行样本单列，不从分母删去。

首轮的 5 次供应商调用全部完成结算，确认为请求包装顺序错误。实验先生成原始输出预算，再在适配器内压低参数，导致真实截断回执被 MODEL_OUTPUT_SCOPE 拒绝。修订候选在请求组装前用实验专用的阶段预算，同一请求生成预占、发送和回执。双方不展示询问人类的工具，因为冻结任务已有完整信息。若请求额外权限，返回原范围拒绝。使用同一本账，先前 5 次均计入 H12 调用与费用，原失败保留。修订候选先串行验证首个 Resume，完成作用域绑定后再执行其余固定试次。

第二轮又完成 3 次有用量的请求。运行器发现合成修复目标的否定词触发产品的全局只读意图，并在一次工具批中遇到恢复守卫，因而停止。这份失败也保留。第三候选为目标改用明确写入意图，模型仍需原样保留测试并逐次调用单一工具。正式运行每题前验证实际产品意图与冻结权限。该措辞校正应用于整套对照，既有 8 次请求仍计入原授权。

第三候选的 40,960 字节传输限制在 DurableModel 标记派发之后检查。冻结首例的零费用回放确认平台报错掩盖了本地限额判断，拒绝的请求没有供应商发送记录。第四候选把实验输入上限调整为 192,000 个保守 Token，先在请求绑定和持久化派发前检查。逐次仍按同一原始账本总金额和次数预占。保留第三候选中已生成终态且所有用量确认的试次，第四候选只补跑其余计划试次。旧的成功与失败样本继续计入，早期含本地协议失败的尝试保留原文件并占用原总预算。各组之前约定的输出、目标、判定器、成功条件及限额保持相同。
