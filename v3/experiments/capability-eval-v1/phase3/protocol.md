## H12-R09

八个 Python 工作区各比较四种策略，共 32 个试次。每题三个独立替换和三条冻结行为断言。完整文件策略在修改文件超过 1,536 字节时注入 length，续写无法再发出完整文件。分块策略逐个提交小型替换。结构化方案一次发送三个带 pre-image SHA256 的替换。校验续写策略在提交第一块之后注入 length，进入既有续写通道，再在第二块结算后、派发前重建 Engine。以原 Run 和操作 ID 关联供给、CAS、真实命令与测试结果。截断率在本轮由夹具注入决定，无法推算生产发生率。所有完整策略须通过冻结测试；任何截断提案被应用、重复执行或改动测试均触发工程失败。

12 项预检含 Python、Node、Go 正常对照及包、文件、版本、命令、工作目录和测试数据故障。用固定离线 Docker 镜像观察实际命令，缺少 examples 的合成项目按原症状单列。Gate 原样拦截，Gate+提示按固定夹具描述补齐经核验的环境输入并重新观察同一命令与测试字节。无 Gate 的一个首次模型调度槽按设计生成反事实对照；此列没有实际请求。先发前的检测、误阻、修复成功和分类以固定故障标签计。该场景是合成复现，独立 R08 Blocked 题保持历史状态。

## H17-R1

30 个不同合成任务，简单、复杂、多文件、跨模块、Research、Coding 各五题。每任务通过 17、419、9841 三个重复控制源文件顺序，任务及臂顺序在首次正式运行前落盘。每臂共用同一初始树、目标、工具能力、运行环境、确定性模型与 32 次调用上限。评审臂增加现有仓库专家工具，专家无写入或测试工具。主流程使用确定性路径执行同一调查或修复。场景为本地内容检索和 Python 更新，组别名称指合成主题和文件范围。

通过规则用同一个与回复脚本分离的判定器，从最终树、原测试与答复取证。任务为采样簇，组内三种顺序作为同簇观测。5,000 次固定 seed 配对 bootstrap 报告 95% 区间。优效要求委派减单 Agent 的成功率差下界大于零且点估计至少 2/30，非劣要求下界至少 −5 个百分点。调整默认值还须总费用不高于单 Agent 的 125%、中位耗时不高于 120%，并与工程硬门兼容。金额和 Token 是夹具用量。现有仓库专家同步执行，报告专家耗时，异步并行等待为不适用。正式真实模型及独立人员复核分别登记状态。
