# E4 写入修复复验协议

基线源码为 `ff1562c`，上一轮验收记录为 `41df5c0`。原 372 条独立输入、标签和未运行的 357 条继续封存。开发使用公开规范、自编中性样本及合成凭据。所有实验使用本地隔离数据库，模型与远程写入预算为零。[原判定](../phase1/acceptance.json) · [计划第 5 节与第 11 节](../PLAN_V1.0.md)

1. 用公开用例测量正常写入、拒绝和提交人工确认。对于拒绝及待确认均检查 PG 中的落库数。对于合法配方，随后验证绑定准确摘要的外部授权确认。保存修复前的所有失败。
2. 区分配方载荷与佐证。提交的载荷必须能追溯到授权范围，独立佐证须与候选摘要、配方内容有别。验证外域、错误版本、未完成工具和无归属哈希的拒绝结果。审计测试涵盖已有记录的脱敏、错误消息脱敏和瞬态失败可重试。
3. 在新候选上运行注册 M02 检查、受影响的调用方、Ruff、mypy，以及原 200 条历史回归。保留首次判定、人工审批与版本竞争结果。H18 使用此前独立八门验收，标明其源码与本轮重测范围。
4. 独立方使用隔离检出编制全新的至少 300 条持出样本，在评分前冻结输入、标签、分层、评分规则和执行器。在公开中性夹具上先检查作用域切换、来源、持久化和回收。开发方只接收可分享的汇总及哈希。
5. 独立方对冻结候选按预注册顺序评分，报告三态准确数、误拒、敏感拦截、人工确认、来源和自证错误、无依据自述的 verified 状态及未执行分母。沿用原硬门和停止条件。完整成绩仅在夹具无缺陷且全部预注册样本完成后签发。
