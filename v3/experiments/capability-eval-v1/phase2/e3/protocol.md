# E3-R1 跨会话记忆对照

开发 30 条合成链、独立持出 10 条；四臂共 640 个会话。每条链有自己固定的 seed，至少一对同版本复用机会。每臂每条链仅第一会话验证成功后可写经验。Coding 场景读取合成配置，交付可核验值，不涉及编写实际补丁。沿用基线的隔离 PG、CAS、版本核验、BM25、spaCy 与配对重排器。开发与持出在同一随机顺序中以隔离项目运行。

每会话至多三次决策。未取得当前证据可读取，已有收据后再次读取会返回带原收据的纠错反馈。系统不会替模型补写答案。需交付值、精确版本、当前证据哈希，且获准证据须来自本次读取或同版本已验证记忆。独立评分方另存其持出答案。规则自检与完整机械对照通过后才签发真实请求。

成功比较与区间以链为配对聚类单位，按分组及拆分列出。全部调用和失败费用纳入每成功会话成本；95% CI 下界大于零才报告可分辨的成本增加。对照成功率差 CI 包含零时记录收益未证实。仅当已知重复错误机会不少于20才计算重复率。已知机会是同臂同链同版本先前出现过的不同错误类型在后续会话中的再现机会。首过指首次提交正确且此前没有错误。重复工具数包含同版本的历史重读，以及被拒的本会话重复读取。记忆采用严格要求当前会话在没有重新取证的情况下交付相同版本的正确结果。历史记忆误用尝试与成功分列。每个交付物以 CAS 字节核验。历史记录及其原两步失败结果保留。

正式 E3 全量授权为开发、持出共用 2,040 次与 US$18。实际矩阵上界 1,920 次。仅发送冻结的合成任务、合法观测和已验证经验。固定 deepseek-flash、thinking enabled、reasoning_effort max，每次最多 4,096 输出。费用是缓存未命中峰值保守上界，和发票实扣区分。单账本持久预占，未知用量保留预占并停发，不重发未知请求。先串行处理首个随机链臂，再处理独立链臂。不同臂的临时 Run/CAS 互相隔离。

在 v3 目录，用含 spaCy 的锁定 Python 与清洁检出的基线 src 运行 controls.py 和 run.py fixture 后运行同目录 run.py formal。目录 manifest.json 固定依赖和输入，所有运行保存到 evidence/CAPABILITY-PHASE2/e3。正式账本位于 formal/ledger.sqlite。恢复时已结算且请求正文相同的步骤复用原回执。
