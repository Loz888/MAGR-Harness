# E1 记忆检索实验准备

E1 的目标是用同一语料和查询，测量 Dense、RRF、重排和来源治理各自带来的检索收益。源码基线为 `4e2fe05487262fee38b9ae0fe67301758c7c6faf`。本轮交付语料、标注草稿和五组排序接线。正式评分为 `NOT_RUN`。[E2 实测报告](acceptance/E2_START_20261120.md) · [E1 准备记录](acceptance/e1-preparation-20261120.json)

## 五组对照

生产 `MemoryStore.recall` 在评分前按项目、仓库和 Actor 筛选，再按时间最多加载 64 条候选。本语料每个主题的同范围最多 35 条。各臂共用同一份已授权候选、同一查询 Commit 和同一时钟。历史和过期记录仍可作为待复核线索出现，分数和版本状态均被保留。实验适配器返回各臂完整排序，以及已进入评分的候选 ID。[候选实现](../../src/mgar_v3/memory/retrieval.py) · [五组适配器](../../src/mgar_v3/quality_eval/e1_retrieval.py)

| 组 | 排序依据 |
| --- | --- |
| A | 纯 BM25 分数 |
| B | 纯 Dense 余弦相似度 |
| C | BM25 与 Dense 的 RRF 融合 |
| D | 使用本地 Pairwise Ranker 重排 C 的候选 |
| E | 对 D 的同一重排分数应用生产可信度、来源有效性、时效和 Commit 权重 |

生产分数默认包含治理权重，故 A–D 用实验适配器提取单阶段分数。E 使用生产命中评分与排序函数。Dense 采用仓库锁定的 `zh_core_web_md 3.8.0` 本地预训练向量。Pairwise Ranker 以仓库已有的 16 组 R4 校准数据生成本地权重，权重、训练数据和向量模型哈希均已记录。

## 就绪验证与正式评分条件

在隔离 PostgreSQL 16.12 上以合成小样验证五组接线。三条正常记录可进入候选，分别来自异项目、异仓库和异 Actor 的三条记录在向量计算前被排除。E 组顺序、分数及版本状态与生产 `hybrid_reranked` 一致。M03 注册回归 12/12 通过。模型 API 调用为 0。

正式运行前需复核开发标签、封存独立持出，并锁定实验时钟、语料、评分规则、模型权重及实验 ID 与 PostgreSQL Memory ID 的映射。原始记录同时保存全候选、各臂得分、排序、模型版本、降级原因及按语料和授权复核的过滤原因。权重或模型缺失时记录对应组未运行。

按原计划输出 Recall@5/10、Precision@5、MRR@10、nDCG@10、ACL 泄漏、过期暴露、错误 Commit 和无答案误报。无答案误报用于统计无可答证据时仍返回候选的比例。召回分母按标注中全部授权相关材料计算，同时报告候选加载阶段的漏召回。以同一查询配对并按主题重采样，报告 95% Bootstrap 区间。正式目标为完整方案相对纯 BM25 的 Recall@5 至少增加 5 个百分点、MRR@10 改善、ACL 泄漏为 0。
