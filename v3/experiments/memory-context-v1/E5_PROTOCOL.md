# E5 记忆检索性能协议

任务书第 8 节。产品基线为 `4e2fe05487262fee38b9ae0fe67301758c7c6faf`。冻结镜像、源码、检索模型、Pairwise 权重、语料生成器、查询和执行次序。

## 负载

- 1,000、10,000、100,000 条记忆分别装入独立 PostgreSQL 数据库，使用项目原迁移和索引。各库含四种记忆、三种作用域、当前和历史版本、有效与过期记录，以及 0–24 个来源引用。
- 合成语料参考 E1 的 1,080 条语义记录和本机匿名聚合，文本、作用域和证据分布由机器记录给出。本机 344 条记录中有 9 条活跃长期记忆和 335 条工作记忆。语料在 8 个被查询的项目中保持成对输入，其余作用域提供背景总量。两个被查询项目随总规模增长，候选上限沿用 64。
- 并发为 1、5、10、25、50 个闭环线程。每个冷热条件测 1,000 次查询。所有算法沿用同一批 64 条查询、过滤条件和请求顺序。返回上限为 8。

| 算法 | 组合 |
| --- | --- |
| BM25 | 权限过滤后的词法排序 |
| BM25 + Dense | 两种分数分别归一化后等权加和 |
| BM25 + Dense + RRF | 现有 Hybrid 路径及 RRF |
| Hybrid + Reranker | 在现有 Hybrid 上接 E1 的本地 Pairwise 重排 |

四组沿用现有 `MemoryRetriever` 的权限过滤和结果治理。BM25 + Dense 用实验的分数融合替换 RRF 算子。向量使用已锁定的本地 spaCy 词向量。

## 执行条件

- 主矩阵每个线程复用一个只读 PostgreSQL 连接。本地向量结果按完全相同的文本缓存，容量为 8,192。每个规模先预热查询和模型，缓存用于比较同一计算配置下的 PostgreSQL 冷热态。
- 冷态在请求前重启本次试验独占容器，用 `pg_buffercache` 确认目标表与索引的主缓冲页为零。闭环负载从这个状态开始，之后随查询自然升温。另汇报请求序号前 100 个的延迟。操作系统页缓存沿用宿主实际状态。
- 热态在同组正式采集前执行 96 次预热，确认目标页已进入共享缓冲。冷热两次必须产生一致的有序结果摘要。
- 每个规模、每种算法补测 40 个单并发原生连接请求，保留按次连接和即时向量计算，核对与主矩阵同样本的返回一致。BM25 + Dense 对照也使用约定的等权融合。
- 数据库本机 Docker 容器限 4 CPU 和 2 GiB。主要会话配置为 `shared_buffers=128MB`、`max_connections=80` 和 `work_mem=4MB`。测量包含当前机器上的 Python 调度与容器通信。

## 指标和复算

请求耗时从线程进入检索到生成结果结束。吞吐以全部闭环线程开始后到最后一个请求完成的墙钟计算。每格保存均值、P50、P95、P99。均值区间按完成时间分块并 Bootstrap 1,500 次。失败和降级单列。

阶段包括权限过滤及候选加载、来源查表、BM25、Dense、融合、重排和结果组装。Embedding 是 Dense 或重排阶段内部的子耗时。组装含检索协调和计时残余。RRF 只适用于 C、D 组。

PG 读行数是相关表的顺序扫描行与索引回表行之和，索引读取项另列。共享缓存命中率使用独立数据库级 `blks_hit` 与 `blks_read` 的增量。CPU 和内存来自本次容器的 cgroup。内存每 250 ms 采样，包含容器内文件缓存。

原始 JSONL 记录每次耗时、各阶段、候选与命中数量、路径、结果摘要及状态。机器报告保留每格原始文件 SHA256、缓存验证和一致性回执。

## 复跑

使用已锁定本地模型的 Python 3.12 环境，从 `v3/` 启动。实验使用本机已安装的 `pgvector/pgvector:0.8.1-pg16-bookworm` 镜像。

```bash
python scripts/memory_context_e5.py freeze --taskbook "$TASKBOOK" --model-dir "$MODEL_DIR" \
  --weights "$WEIGHTS" --out "$FREEZE"
python scripts/memory_context_e5.py run --freeze "$FREEZE" --freeze-sha256 "$FREEZE_SHA" \
  --model-dir "$MODEL_DIR" --weights "$WEIGHTS" --out "$RESULTS"
```
